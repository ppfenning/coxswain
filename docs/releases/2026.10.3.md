# 2026.10.3

Cut on 2026-10-23. Status: **beta**. A patch that makes `cox setup doctor` clean on a migrated machine and lets
the board sync see a working GitHub login on an older `gh`.

**The doctor stops flagging healthy machines.** Every migrated host reports its home's `providers` folder beside the
checkout, where `setup migrate` copies a team provider profile; the doctor now counts that folder as migrated
instead of telling every host to run `setup migrate`. With the shipped-cartridge fallback of 2026.10.2 a workspace
needs no `base` or `local` cartridge links, so none found is no longer a failure; stale links still fail.

**The board sync sees the login.** The route sync's check ran `gh auth status --active`, which `gh` 2.46 (Ubuntu's
package) does not know, so every land on such a machine reported `gh is not authenticated`. It falls back to
`gh api user`, which works on every version.

**Docs.** Each section links to its own page instead of listing it again as its first child, a component's README
is titled README, and the graphs' reference pages and specifications sit in their own subsections.

## coxswain (umbrella)

- docs: sections link to their own page; component READMEs and graph pages stop repeating names (coxswain #378)
- gh login check on any gh; doctor: home providers folder and no cartridge links are fine (coxswain #379)

## Known gaps

A profile with no `store` block still reads as `files` even when its provider profile names the shared store, and
the doctor warns about the mismatch; set it with `cox settings set profile store.mode shared` on each machine that
uses the shared store.
