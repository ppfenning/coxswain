# 0.2.0

Cut on 2026-09-06. Every component is tagged `v0.2.0` in lockstep; `coxswain-tools` is published to
PyPI from that tag. Status: **beta**. The version string drops the `-beta.1` suffix: under zero-dot
versioning the major already says the interface may move and the minor is where breaking changes go.
**Breaking:** the HUD and desktop are no longer components, and `policy.gate` defaults to `ticket`.

## coxswain

- The HUD and desktop leave the product: four components, not six; `cox install --with hud|desktop` and
  `cox hud` are gone, and the voice loop lives on in its own repository (#25, #26).
- The methodology states what a graph may not do: a graph owns sequence and writes nothing, one harness
  owns every consequence (#24); the front page, tagline, licence and animated header (#16–#21); the README
  is the package's long description (#22); post-rename repository names and resolving docs links (#23).
  Manifest and notes (#27, #28).

## coxswain-cartridges

- `policy.gate` declares one of four human-gate levels, default `ticket` — the harness proposes and a
  person merges — tighten-only through the chain (#44).
- The project layer: a target repository's `.agent/cartridge.yaml` merges last, four keys allowed,
  tighten-only, and runs record an `overlay_sha` (#37, #41).
- Reviews run at the standard tier, arbitration stays deep (#40); the reviewers keep their dollar ceiling
  after the move (#43); the plan skill has a read budget (#39); size counts source lines, tests are
  reported, never refused (#36); `policy.pacing` and a priority on work items (#34, #35); the route-work
  and runs skills open by checking the leader (#38).

## coxswain-graphs

- The harness reads the project overlay at the edge and passes it to `load(overlay=)` (#45); the trust
  runbook documents the layer and trap observations carry `overlay_sha` (#46).
- A build's size target counts source lines and reports test lines beside them (#44); the handoff no
  longer asks for evidence the harness measured (#42); a validator that answers with a placeholder twice
  abstains, and its evidence request must name a real path (#43, #47); review tiers (#48); a pacing stop
  verdict zeroes the free slots (#41).

## coxswain-tools

- `cox runs detail RUN` — node timeline, standing objection, quarantine reason, last tool calls; `ENTER`
  from `runs top` (#50, #54).
- `cox runs notify` — desktop notifications for exits, quarantines, budget stops and cost (#52).
- `cox route leader take|beat|release|status` — one file says who drives the landing loop; `route launch`
  and `runs land --apply` refuse while another live session holds it (#51, #56, #57, #60).
- `cox dev release-check` — CLI surface, manifest and release-notes citation checks; `cox dev release`
  refuses to tag while a drift stands unless `--allow-doc-drift` says why (#53, #59, #61).
- `cox route file --from-intake` links an intake file to its initiative and retires it; `route status`
  shows queued, decomposed and landed (#55).
- `cox usage assess` and pacing: a window gatherer, a tighten-only tier and effort ceiling on `route
  launch`, a stop verdict honoured by a pure launch gate (#38, #42, #44, #45, #48).
- `runs land` runs checks with the project's own interpreter and waits for checks to register (#49, #63);
  `cox setup` gains the cartridge editor (#39, #41); the HUD command surface is removed (#66, #67);
  `pyproject` bumped (#68).
