# 2026.11.5

Cut on 2026-11-05. Status: **beta**. This release is mostly about keeping a multi-phase initiative moving under ticket landing. A later phase no longer deadlocks behind approved work that waits for the final pull request, a phase whose tasks were approved in earlier runs counts as complete, and phases get a done status that a land can act on. Epics now group initiatives, and an initiative can land on a configurable branch instead of the default. Most lint stops that used to kill a run now heal and leave a note, and lanes spread across hosts by the load they actually carry.

**Ticket landing without deadlocks.** Under `land_at: ticket` an approved task is held for the initiative's one pull request, and a later phase that needed it used to wait forever. A need on an approved task now counts as met at the land granularity the chair plans with, in the docket, the runnable verdict, the work store's ready set and the harness launch, and the chair reports an open deadlock once instead of every tick. A phase whose tasks were approved in earlier runs counts as complete for its dependents, and validate-phase runs over the phase's stored tasks, not only those built in the current run. Before a phase builds, a ticket stack refreshes onto current main, and a stale base is reported instead of building an empty patch. A stranded row for a task the store has back at ready no longer blocks relaunches.

**Phases are done, and lands take whole phases (operator issue 806).** A phase is `done` when every task is done, dropped or approved and the phase is validated. A done phase lands its phase branch onto the default branch, or onto an open pull request branch with `--base`. The land's plan replaces the "exactly one commit ahead" check with an ahead-of-base check, accepts multi-commit phase branches, and a refusal reports the commit counts it compared.

**Epics and target branches.** An epic is a named group of initiatives: an intake or initiative names its `epic`, an optional `epics/<id>.md` file gives it a title and a `target_branch`, and the chair status line and `cox route status` show each epic, and the dash feed carries it, with its initiatives and how many have landed. The branch an initiative lands into resolves from the initiative, then its epic, then the team cartridge's `landing_areas.target_branch`, then the repository default. A target branch that is set but unusable refuses the land or launch instead of falling back to the default.

**Lint that heals.** A home or absolute path in an intake's text is rewritten to a neutral phrase and recorded as a `lint:` note instead of refusing the decompose, and `route file` and `route edit` run the decompose's own reach check so filing and planning agree. A surface naming a file the task creates but missing its ` (new)` marker is marked and noted by the decompose and the start-of-run check instead of quarantining the task.

**Lanes and the chair.** Lane placement ranks hosts by the lanes they already run, so work spreads instead of piling onto the highest-capacity host. Each build lane gets its own test database, so parallel levels no longer share one. An empty decompose waits for a remote decompose to be fetched before it is reported. A fetched remote epic's approved task reaches the store as approved. Chair session and agent costs no longer read as zero. One `cox upgrade` installs the target towpath, and an old towpath fails the upgrade instead of passing it.

**Releases.** The merge-back waits for its pull request's checks before merging, and a resumed release looks up the rehearsal by the tagged commits.

**Towpath (dash).** Running phases in the queue have a colour, and a done state shows green without waiting for landed. Towpath does not draw epics yet; the feed carries them for a later release.
