# 0.29.0

Cut on 2026-10-05. `coxswain-tools`, `coxswain-graphs` and `coxswain-cartridges` are tagged `v0.29.0`.
`coxswain-dash` and `coxswain-crew` stay pinned at `v0.28.0`. `coxswain-tools` is published to PyPI from its tag.
Status: **beta**. This release has one headline, and the umbrella's install docs follow it: git and curl are the
prerequisites, and `uv` downloads a managed Python 3.14 when the system one is older.

**Python 3.14 is the supported floor.** Every Python component requires Python 3.14 or newer, every CI job runs on
3.14, and the old 3.12 floor job becomes a non-blocking 3.15 canary. Coxswain installs through `uv tool` and the
Homebrew tap, which bring their own interpreter, so most installs need nothing new.

**Upgrading from 0.28.0.** Reinstall with `uv tool install --python 3.14` (or `uv tool upgrade`), which fetches a
managed 3.14 if the machine has none. Rebuild any development virtualenv on 3.14. The store schema is unchanged and
nothing migrates.

## coxswain-cartridges

- `requires-python` is `>=3.14`, CI runs on 3.14, and the floor job becomes a 3.15 canary (cartridges #178).

## coxswain-graphs

- `requires-python` is `>=3.14`, CI runs on 3.14, and the floor job becomes a 3.15 canary; the retry helper uses type
  parameters (graphs #682).

## coxswain-tools

- `requires-python` is `>=3.14` in the pyproject, `.python-version` and the lock, CI runs on 3.14, and the floor job
  becomes a 3.15 canary (tools #1320).

## coxswain

- `requires-python` is `>=3.14` in the pyproject and the lock, the releasable workflow runs on 3.14, and the
  install docs drop the Python prerequisite that `uv` now covers (coxswain #225).

## Components

`coxswain-tools`, `coxswain-graphs` and `coxswain-cartridges` carry the new floor; `coxswain-cartridges` rejoins at
this release from v0.23.1. `coxswain-dash` and `coxswain-crew` are unchanged since v0.28.0.
