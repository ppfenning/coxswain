# 0.48.0

Cut on 2026-10-19. Status: **beta**. A fix release: a decompose now reads the repository its intake targets. Only
coxswain-tools changes.

**A decompose reads its repository.** `cox route launch decompose` started the harness without `--repo`, so the
decompose seats had the workspace as their only readable directory. On 2026-10-19 every seat of a decompose reported
that read permission was refused on the target checkout, and the plan named modules that do not exist and missed
most of the files the change touches. The launch now passes the intake's `repo:` to the harness, expanded on this
machine and as written for a lane host. The seats get the repository as a readable directory, a digest of it, and
its cartridge overlay, as an epic already does. An intake without `repo:` launches as before.

The release also carries `agent_tools/state_paths.py`, the first part of moving runtime state out of the workspace.
It is a pure module that classifies a runs file as runtime state or record and names its folder; nothing calls it
yet, and nothing moves.

## coxswain-tools

- `route launch decompose` passes the intake's `repo:` to the harness (tools #1829).
- `state_paths`: a pure classifier for runtime state and records, not yet wired in (tools #1830).

## Known gaps

Runtime state still lives in the workspace's runs folder; the readers and writers move in a later release, and the
checkpoints and traces that coxswain-graphs writes are not yet covered. An intake row is not linked to its initiative
when it decomposes, so it stays `queued` after its work lands.

The gate for 0.48.0 was the hosted rehearsal (run 39253123329), whose fresh, upgrade and migrate jobs passed, and a
clean-machine rehearsal in a throwaway Proxmox container, where the fresh install, the upgrade from 0.47.0 and
`cox setup migrate` passed. Both ran on tools 3402a34, graphs 0c138e2, dash b654297, cartridges 8584e34 and crew
80eb36a.

Migrations: none

## Components

coxswain-tools changes and is released at 0.48.0. coxswain-graphs has no commits since v0.43.0 and stays pinned there,
coxswain-dash has none since v0.42.0 and stays pinned there, coxswain-cartridges has none since v0.40.0 and stays
pinned there, and coxswain-crew is unchanged since v0.38.0 and stays pinned there.

**Upgrading from 0.47.0.** The store schema is unchanged and nothing migrates on its own. Update `cox` itself first,
with `uv tool upgrade coxswain-tools` or `brew upgrade cox`, then run `cox upgrade`.
