# 2026.10.4

Cut on 2026-10-28. Status: **beta**. A patch that gives a Homebrew install a way to get the optional extras back,
makes `cox versions` work from any directory, and fixes how `cox runs` counts resumed sessions.

**Optional extras survive a `brew upgrade`.** The new `cox setup extras` installs the traces, parquet, lake and
postgres extras into the running `cox`'s own environment from pinned, hashed wheels generated from `uv.lock`, so a
Homebrew install no longer needs hand-injected packages. `--with` picks a subset and `--dry-run` prints the plan. The
doctor's store and shared-store rows now name this command. The wheel also ships `providers/catalog.yaml`, the file
the model freshness check reads.

**`cox versions` works from any directory.** It resolves the manifest from the recorded home instead of the current
directory. `--home` is new; `--root` and `--manifest` still override it.

**Resumed sessions are priced by delta.** `cox runs` usage prices each call against its session's last total by the
runner's own rule, so a failed call between two successes, or a budget stop, no longer inflates the cost.

## coxswain (umbrella)

- `cox versions` resolves the manifest from the home, not the current directory (coxswain #382)
- runs usage counts resumed sessions by delta (coxswain #383)
- the Homebrew wheel ships the providers catalog (coxswain #384)
- `cox setup extras` installs the optional extras from pinned hashes (coxswain #385)
- one `package-data` table in `pyproject.toml` after #384 and #385 both added one (coxswain #386)

## Known gaps

`cox setup extras` runs pip from the `cox` environment, so a uv-tool install, whose venv has no pip, is not covered.
It has not been run against a real Homebrew venv; that check happens on the machines after the release.
