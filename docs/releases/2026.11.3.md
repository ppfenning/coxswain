# 2026.11.3

Cut on 2026-11-04. Status: **beta**. This release finishes the two initiatives that 2026.11.2 shipped only in part: landing at a configurable granularity and intake queue control. It also makes the chair's own spend visible, adds a monthly budget for plans that have no five-hour or weekly limit, and gives towpath a task tree under each run. Chair lands now run beside the tick, so launches no longer wait behind CI. The rest is a day of harness fixes from a session chair driving the fleet through 2026.11.2.

**Landing at a configurable granularity (#620).** `land_at` is `ticket`, `level` or `task`, set in the team cartridge, a repo overlay or one initiative's frontmatter, with `ticket` as the default. At `ticket` an initiative opens one pull request in total: task branches merge into their level branch, the merge is written to the store, and a merged phase unblocks the next phase without waiting for a land. The chair and the epic driver now agree on when a ready task beside an unlanded sibling may run. This repository's overlay sets `land_at: level`.

**Intake queue control (#606).** The chair honours the store rules that 2026.11.2 added. `cox route file --after` and `cox route edit --after` make an intake wait until the named intakes or initiatives land. `cox route hold` and `cox route release` take an intake out of the queue and put it back. `cox route priority` orders queued intake, and `cox route remove` takes several ids. `cox route status` shows what each item waits on and what is held. The autonomous chair page and the route reference describe them.

**Chair and agent spend (#631).** The dash feed reported the chair session by its short id, which never matched the transcript's full session id, so the chair session and its agents always showed $0. The readers now match on the prefix, and `cox setup` repoints a workspace's price catalog link that an upgrade left dangling.

**A monthly budget (#632).** `monthly_budget_usd` in the profile, with an optional `budget_timezone`, measures spend against the calendar month. `cox usage assess` reports month-to-date spend, the daily average and a straight-line projection, with a verdict of on track, over pace or over budget. The hard-stop fraction applies to the monthly budget, so the chair pauses launches before the month is overspent. `cox dash --feed` carries a `budget` object.

**Requeue gives a fresh initiative id.** A requeued intake whose id is still held by a dropped initiative now gets a fresh initiative id. `cox route file`, `cox runs` and the chair's launch all use it, and the requeue says which id it chose.

**Harness fixes.** Chair lands run in their own process beside the tick, under the same land lease and per-repo cap. A chair loop renews the lease it was handed, and a land lease held by a dead process on this host is taken at once. Decompose launches place by the hosts table and run on remote lanes like epics, and `cox route launch decompose` accepts `--run-id`. A remote run's fetch brings its phase branches back, and a phase land fetches again before it calls a missing branch a conflict. A decompose writes its tasks as store rows, writes a task with needs as ready, always records the intake's repo, and stops relaunching on a dangling need from a withdrawn task. Its layout check accepts a surface named by a shorter path or its stem, keeps a directory surface, and adds a named test file to the surfaces instead of refusing the plan. Surface checks read the fetched default branch. A task that changes the command table gets the generated README as a surface. `cox route file` and `cox route edit` take `--link`. Chair export never deletes a ticket that a live decompose still holds, and a task set back to ready after a land conflict leaves the stranded list. A remote launch syncs the workspace cartridge. The tap formula never builds pyarrow from its sdist. A development install builds towpath from the dash checkout and rebuilds it after a dash land.

**Towpath (#158).** Each run on the runs page expands into a tree of phases and tasks, with each task's stored state, tries and reason. A collapsed run reads `N runs` and shows its landed and quarantined counts in place of ATT, and the headers read RUNS, TRIES, PHASE and STEP. Inbox entries open to a full detail view with actions, and stale entries are marked. Dash lane checks run the same clean check as CI. `towpath --version` prints the commit on a development build.

## Known gaps

Two pieces named for this release are not in it. The release check still reads the CLI surface by walking `cox --help`, not from the command table (#163). Towpath has no view of the monthly budget yet; the `budget` object is in the feed only. Per-task lane scheduling still waits on the waves-of-phases work (#626). This repository lands at `level`, not the `ticket` default, so its own initiatives still open one pull request per phase.

Cut with `--allow-doc-drift`: `release-check` reports the same three drifts as at 2026.10.4 through 2026.11.2 (the dash component page lives at `docs/components/dash/`, the package description is two sentences, and `graphs/README.md` names the `agent-graphs` ledger directory).

## Upgrading

The store schema stays at version 15; this release adds no store migration. To pace against a monthly budget, set `monthly_budget_usd` (and `budget_timezone`, if the month should not follow the default time zone) in the profile. This release declares no `cox migrate` migrations.
