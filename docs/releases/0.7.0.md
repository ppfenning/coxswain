# 0.7.0

Cut on 2026-09-16. Every component is tagged `v0.7.0` in lockstep; `coxswain-tools` is published to
PyPI from that tag. Status: **beta**; nothing here breaks a `0.6.0` install. This release closes intake
groups **G3 work shape**, **G4 validator reach** and **G6 release discipline**, and lands the tools half of
**G5 cost bounds** and the cartridges half of **G7 triage** — the theme is that the loop stops throwing
approved work away, and the tools tell the truth about what a run cost. Versioning from here: cartridges,
graphs and tools stay in lockstep; crew keeps its own tag from the next release.

## coxswain-graphs

- The sweep graph exists: `graphs/ops/sweep.py` with `sweep_plan`, harness-run `sweep_apply` and a
  no-model `sweep_verify` (#83), registered in `_KNOWN_GRAPHS` and the CLI (#84), with its `SPEC`, table
  rows and page (#85); the docket marks `sweep` runnable when an idea is queued (#86) and the dispatch
  schema carries `shape` with a required `why` (#90).
- The epic emits a `consolidate` proposal on the finding class work-shape.md §4 names (#92).
- Every run removes its worktrees and prunes dead registrations on every exit path, `--keep-worktrees`
  moves them under `_kept/<run>` (#78, #82).
- `lint_tickets` runs at the end of decompose: reach and coupling refuse with corrections, grant and
  size attach as `lint:` advisories on the ticket (#79); the reach rule now refuses corpus paths (#93) and
  the trust runbook says what a seat can see (#94).
- An escalated, approved task reads `approved` in the work store, not `done` — the disagreement between
  the store and git that stranded nine tasks on 09-09 is closed at the source (#91).
- The validator judges what the harness saw: every call record carries a `task_id`, and a task's evidence
  array holds its trace-observed commands keyed by it instead of by which files it touched (#96); the
  brief says so (#95); a refusal must name a defect with a file, is retried once when malformed, and is
  recorded `abstained` rather than discarding an approved patch (#97).
- An arm's `BudgetStop` quarantines the task as `infra` with the patch kept and the run exits normally
  (#88); a node failing mid-review writes the task record on the way out, `infra`, patch kept (#89); a
  provider safeguard refusal is retried once on the tier's alternate model (#81); a failed configured
  check reaches the task record and the fix-loop brief by name and output tail, never "see evidence" (#87).
- The coverage-floor trim runs `pytest` through the current interpreter, so a land's fresh checkout no
  longer fails it (#80).

## coxswain-tools

- `cox dev release` bumps what it tags (branch, PR, wait, merge — reusing the land executor) (#137), waits
  on the workflows each tag starts and refuses to call the release done on any failure (#138), and
  `release-check` gains a `versions` check `gate` never allows by reason (#136).
- `release-check` compares the CLI surface against the docs generator's output rather than the tree
  (#135) and stops demanding a version string of component pages that never carry one (#139) — 48 false
  drifts on a clean tree become 7 (see known gaps).
- `cox stats bounds` reports, per (role, model), n, p50, p95, max, the declared ceiling, whether the
  distribution is censored by it, and the strict/moderate/liberal candidates; `--write` produces the
  bounds file the harness will read (#144, #145). `cox stats spend-mix` splits cost by token class per
  model — output is 40–69% of spend, cache reads under a third (#146).
- The operator's spend ceiling lives in the profile's `spend:` block and reaches `usage_window`, so
  `route context` reports a measured window instead of "unmeasured" (#143).
- `route.parse_frontmatter` reads block-style lists (#140); `route context`/`status` validate item states
  when they read them and show `approved` as awaiting merge (#142); `cox runs notify` seeds its state from
  disk on first start instead of replaying 389 runs to the desktop (#141).

## coxswain-cartridges

- The `ticket_amend` write kind (risk low, ramp eligible) and a `triage` role ceiling (#69).
- Ledger rows may carry `model`; `SCOPE_KEYS` gains it, so a streak earned under one binding does not
  transfer to another (#70).

## coxswain

- The nightly `releasable` workflow checks each component the way its own `ci.yml` does and installs the
  public substrate for graphs; it had failed every night since 09-09 on a guessed install step (#40, #41).

## Known gaps

- `release-check` still reports 7 false `cli_surface` drifts — the bare `cox` and the `setup`/`dev`
  groups read as commands to remove — so this release was cut with `--allow-doc-drift`; filed.
- The fix loop can still build a third time it never reviews; the ticket for it is at the attempt cap
  awaiting a person, as is the dispatcher counting itself as a slot.
- Four route.py fixes (lint honours `needs`, deterministic `initiative.md`, land closes `approved`,
  `runs usage` on a live run) and the graphs/cartridges halves of G5 and G7 are in flight for `0.8.0`.

## Components

`coxswain-graphs`, `coxswain-tools`, `coxswain-cartridges` and `coxswain` carry the changes above.
`coxswain-crew` is unchanged since `v0.4.0` and is tagged in lockstep for the last time.
