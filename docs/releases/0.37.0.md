# 0.37.0

Cut on 2026-10-11. Status: **beta**. The first release after the feature freeze: it fixes the defects the
2026-10-07 bug scan found and hardens the chair loop, so a stuck land, a hung call or a dead feed no longer
stalls the queue.

**A loop that does not hang.** Calls on the chair's tick path and its store connections carry timeouts, a refused
land retries on a bounded back-off, and the repository land lease is renewed for as long as the land runs. The
red-main revert reruns a flaky check before it reverts and never leaves the checkout on its branch. A land's
wait for checks sees a startup failure and bounds a required check that never appears.

**Runs.** Store writes during a run are retried, and network calls in a run time out and kill their process group.
A test failure outside a ticket's surfaces is a ticket cause that names the files. Decompose sizes an intake first,
so a one-ticket intake becomes one task.

**Deferred to 0.38.0.** Two quarantined tasks of the login check (`host-doctor-local-branch` and
`login-check-evidence-and-two-strikes`); the release fetching before it tags; the chair service unit's doctor PATH
row; the runs STATUS chip's remaining task; the release notes' cheap opener; and the claude runner's process-group
kill.

**Upgrading from 0.36.0.** Nothing migrates and the store schema is unchanged. Restart the chair loop. A cartridge
may list repositories under `epic_threshold.inline.repos` to let the chair work a change of at most
`epic_threshold.inline.files_max` files inline; the list is empty by default, so nothing changes until you opt in.
