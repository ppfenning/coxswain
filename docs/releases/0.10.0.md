# 0.10.0

Cut on 2026-09-17. `coxswain-cartridges`, `coxswain-graphs` and `coxswain-tools` are tagged `v0.10.0` in
lockstep; `coxswain-crew` is unchanged and stays pinned at `v0.7.0`; `coxswain-tools` is published to PyPI
from its tag. Status: **beta**; nothing here breaks a `0.9.0` install. This release is the fast follow the
release tooling itself needed: the planner now gathers component versions at the edge, writes the releases
index section, judges the tag-triggered workflow runs, publishes a GitHub Release for every repository it
tags, and `release-check` no longer reports drifts that were never drifts — so this is the first cut made
without `--allow-doc-drift`, and the first to appear on GitHub's Releases pages.

## coxswain-tools

- The tools release planner gathers each component's pyproject version at the edge and refuses a cut
  whose manifest and pyprojects disagree (tools #167); its notes check accepts citations of the umbrella
  repository (tools #170); `package_pages` judges a README's H1 by the package's own name (tools #168).
- `release-check` in tools gains a `release_index` check that reads the umbrella's releases index in its
  own table shape, and `cox dev release` writes that section itself instead of leaving it to the chair
  (tools #169, #174, #175).
- `wait_workflows` in tools waits on the runs the tag itself triggered, not the commit's earlier runs
  (tools #172).
- `cox dev release` in tools publishes a GitHub Release for every repository it tags — the umbrella with
  the full notes, each component with its own section and a link back — editing an existing release
  instead of duplicating it; a pinned component gets none (tools #171, #173).
- `cox dev release backfill-github-releases` in tools walks the existing tags oldest first and creates the
  missing Release objects — or edits a stale body, or reports one already current — reading each version's
  own manifest for a pinned component's tag (tools #179).
- `release-check`'s `cli_surface` in tools treats the program name and a group that only holds
  subcommands as namespaces, ending the seven standing false drifts (tools #177).

## Known gaps

The three `graphs-loop-fixes` tickets at the attempt cap, the decompose's stale `initiative.md` on a
relaunch, the doctor's schema readers for the other two components and a handful of small loop defects roll
forward; the P projects — vendor axis, home/ctop, command table, router and steward, courier — begin next.

## Components

`coxswain-tools` carries the changes above; `coxswain-graphs` and `coxswain-cartridges` are re-tagged in
lockstep with no changes of their own. `coxswain-crew` is unchanged since `v0.7.0` and stays pinned there.
