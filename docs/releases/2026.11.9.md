# 2026.11.9

Cut on 2026-11-13. Status: **beta**. Three fixes from the first day the landing model carried a real initiative end to end, nine phases of a client in another repository. The board read 0 of 9 phases while all nine had merged into their initiative. The lander then waited for ever on that repository's pull request, which had no CI to report, and every other land on the machine waited behind it. And personal machines can now follow `main` on an edge channel.

**The board.** A phase the lander merged into its initiative reads merged and counts as done. An approved task in an initiative the lander tracks is merged into its phase tip, so it reads merged and meets its siblings' needs. An initiative still leaves the queue only when it lands on its parent.

**The lander.** A branch with no CI workflow merges on the gate checks the lander ran before it opened the pull request, instead of waiting for checks that never come.

**The edge channel.** `upgrade_channel: edge` in a machine's profile, with `cox upgrade --install-timer`, moves the install to the newest commit on `main` whose CI passed, restarts the chair and lander when the commit changed, and moves back if `cox setup doctor` then fails. `cox upgrade --to` now takes a commit SHA.

## Known gaps

A quarantine still waits for a person: the chair retries one the harness caused, and nothing yet decides a failed check or a review objection on its own. The lander still blocks for the length of a CI run on a repository that has CI. The feed has no task-level `waiting` word yet, so a task behind an unmerged sibling still reads blocked. The edge timer is Linux only, and an edge rollback is refused once the new commit's store migration has run. The gaps listed in 2026.11.8 stand.
