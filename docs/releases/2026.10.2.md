# 2026.10.2

Cut on 2026-10-23. Status: **beta**. A patch for what running one target repository's work through the chair
turned up, plus a docs pass.

**Filing and launching one-task work.** `cox route file` without `--intake` names the task `<slug>-task` and files
the initiative row in the store beside it. Before, the task shared its initiative's id, the store kept only one of the
two rows, and launch refused with `no initiative row`; `route edit` could not address the task either. `--body`
given text instead of a path says so instead of printing the whole body as a file name.

**Logins.** A lapsed Claude login stops the run without quarantining the task or spending an attempt, so the next
launch on a logged-in host builds it. The remote login check runs the `claude` binary (`command claude`), not a shell
function of that name: a startup file's `claude()` wrapper made the check pass while every lane on that host failed
to authenticate.

**Cartridges.** A cartridge the workspace's `cartridges_dir` lacks is read from the ones this checkout ships, so a
workspace needs only its own team cartridge and never a symlink into one machine's install.

**Docs.** A component's pulled README no longer replaces its page, and the pulled component pages and the generated
CLI pages join the nav, so every page has previous and next links. The docs call the routing session the chair
throughout, and stale claims about bare `cox`, install, migrate and upgrade are corrected.

- cartridges: fall back to the shipped cartridges for a name the workspace lacks (coxswain #373)

## Known gaps

One-task initiatives filed before this release still hold a single colliding row in the store; refile them, or
upsert the task under `<initiative>-task` and an initiative row under the initiative id. A workspace that tracks
`cartridges/base` and `cartridges/local` symlinks keeps working, and can drop them once every machine runs
2026.10.2.
