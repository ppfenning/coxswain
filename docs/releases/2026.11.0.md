# 2026.11.0

Cut on 2026-11-01. Status: **beta**. A release that makes the autonomous chair actually finish work without a
person. In 2026.10.5 its own lands were refused by its own lock, a task sent back for a rebuild was left stranded,
and idle lane hosts dropped out of placement between check-ins. This release fixes those, makes each chair round
much faster, moves the macOS builds off the runner GitHub retires on Nov 2, and adds no store migration.

**The chair lands its own work.** The chair now passes its own label on every `cox runs land` it starts, so the
landing guard no longer refuses it as an unlabeled caller. A task sent back with `cox route edit --state ready
--rebuild` is marked rebuilt, so its old approved run no longer counts as stranded and the chair relaunches it. When
a rebuilt task lands, it replaces the branch its closed PR left behind instead of failing the push. Lane checks
now run the same personal-reference check CI runs, under `--require-names`, so a host or user name in a test is
caught before review rather than at land time.

**Work spreads across the fleet.** A remote launch runs on the host the chair placed it on; in 2026.10.5 the
remote host placed it a second time and the chair recorded the wrong host. Hosts with no weight set are ranked by
their free lanes for their size, so a ten-lane host is chosen ahead of a four-lane one. The chair beats each active
lane host often enough that placement never treats an idle host as stale.

**Faster chair rounds.** Gathering a round's facts took 45 to 130 seconds. Intake matching now parses each
initiative once per round, the idle check reuses the round's reads, and the per-PR `gh` calls run concurrently and
are cached for a few minutes.

**Smaller fixes.** Bare `cox` starts a fresh chair when the crashed holder's Claude session was never saved,
instead of failing on `claude --resume`. A queue task under a live run reads running in the dash feed. `cox route
remove` refuses only for runs live on the initiative it removes. A task finished outside `cox runs land` still
records its merged PR. The coxswain-dash release and coxswain's install proof build on `macos-15` runners.

## Known gaps

Lands into one repository still run one at a time, and each waits for CI before it merges, so a queue of approved
work in one repository drains at roughly one PR every eight minutes. Routing lands through GitHub's merge queue was
built but did not pass review in time for this release. The chair still makes a second land attempt after each
successful one; it logs "already landed" and changes nothing. Lane checks now need `COXSWAIN_CLEAN_DENY` set on
every lane host and in the chair's environment, and a host without it fails every land's checks.

Cut with `--allow-doc-drift`: `release-check` reports the same three drifts as at 2026.10.4 and 2026.10.5 (the dash
component page lives at `docs/components/dash/`, the package description is two sentences, and `graphs/README.md`
names the `agent-graphs` ledger directory), plus three false drifts on the release index. Its index rule expects the
2026.10.0, 2026.10.3 and 2026.10.4 sections to show dash at their own version, but those releases pinned dash at an
older tag and their sections say so correctly.

## Upgrading

No store migration and no `cox migrate` migration. Before upgrading a lane host, set `COXSWAIN_CLEAN_DENY` (the
same regex as the repository's CI secret) in the environment its lanes and the chair run with: lane checks now run
`check_clean.py --require-names`, which refuses to run without it. Upgrade the chair and the lane hosts together.

Migrations: none
