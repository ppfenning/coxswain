# 2026.11.1

Cut on 2026-11-03. Status: **beta**. A release of fixes for what went wrong on 2026-11-02, the first day a chair
ran 2026.11.0 unattended. That day PRs merged on GitHub and were left stranded as approved, a session chair lost its
lease to its own service loop, decompose wrote tasks into directories that did not exist, and a queue of approved
work in one repository drained one PR every eight minutes. This release fixes those, lets a repository run more
than one land at a time and skip the local checks its required CI already runs, and adds no store migration.

**A merged PR is a landed PR.** In 2026.11.0, a land into a checkout on a detached HEAD failed after GitHub had
merged its PR, because the forge CLI's local branch cleanup cannot run there, and the task stayed approved. A merge
now counts when the forge reads the PR as merged, whatever the CLI's exit code, and keeps the CLI's text as a
warning. A land whose post-merge step fails still marks the task done and logs the error. A phase whose PR is
already merged, or whose commit is already on the target branch, lands as a mark-done only, and the chair stops
planning it again. Lands also refuse to run in the install checkout itself: a release install on a detached HEAD
is refused with the name of the working clone to use, and a development install on a branch lands with one line
saying it moves the code the chair runs from. Filing against the umbrella repository records the new
`umbrella_clone_dir` working clone, never the install path.

**The chair lease holds.** `cox route chair take --steal` now takes a live chair and names the holder it displaced.
A session holder whose pid is alive and whose `until` has not passed reads live without a heartbeat, so the service
loop no longer takes its lease early. The store lease row now lasts as long as the takeover, and the loop takes it
back only when the session's pid is dead or its `until` has passed. `--hours` on a retake of your own chair moves
`until`. On a development install, the chair loop exits with code 75 when its checkout's HEAD moves, and the unit
`cox chair service --install` writes restarts it on that code, so the chair runs the code that just merged.

**Decompose writes what lint accepts.** Decompose marks a surface for a file it creates as `(new)`, and the ticket
lint flags a plain surface that does not exist. Decompose creates a new phase directory before it writes the tasks,
and withdraws a partial initiative when any task fails to write. The work-store DAG check again refuses a live item
that needs a dropped one. An epic prints a line for each phase awaiting the land of approved tasks, with one land
command per task, and its summary counts them.

**Faster lands.** The land repo lease now has slots. A repository's `land_limit` (in `.agent/cartridge.yaml`,
default 1) lets that many lands plan, build and check at once; only the merge is serialized, under a short
`merge:<repo>` lock. A repository can also set `landing_areas.land_checks: ci`, so a land skips its local checks and
waits on the forge's required checks instead. It keeps the local checks, and says why, when the required checks
cannot be read. coxswain itself now sets `land_checks: ci` and leaves `land_limit` at 1.

**Smaller fixes.** The usage gate no longer holds a window on a burn projection before a quarter of it has
elapsed, and it gives its headroom in the window's own unit. A launch from a session finds the lane Python from the
install's venv. Partial lands and the chair's other `git -C` callers expand a tilde repository path. `cox route
edit` refuses only for a run live on the initiative it edits. `cox runs triage` prints the review findings and the
fix loop's checkpoint reason. `cox settings set` edits only the target line of a profile that holds a flow-style
mapping. In the bare `cox` chair offer, attach has its own key, and an idle chair loop honours a takeover release
request. The Homebrew `cox` formula ships the psycopg driver, so `brew upgrade cox` keeps a postgres store working.

## Known gaps

A repository still lands one PR at a time unless its overlay sets `land_limit`, and coxswain's own overlay does not
set it yet, so coxswain's lands gain only from `land_checks: ci`. Two lands that conflict still race: the second
stops on the conflict and is retried on the next tick. The forge's merge queue is not used.

Cut with `--allow-doc-drift`: `release-check` reports the same three drifts as at 2026.10.4 through 2026.11.0 (the
dash component page lives at `docs/components/dash/`, the package description is two sentences, and
`graphs/README.md` names the `agent-graphs` ledger directory). The three false drifts on the release index are gone
since #533.

## Upgrading

No store migration and no `cox migrate` migration. On a host whose profile `umbrella_dir` points at the install
checkout, set `umbrella_clone_dir` to the working clone before you file against the umbrella repository: filing
refuses without it. Then run `cox route paths --move <install path> <working clone>` to list the open records it
would move, and again with `--apply`. To get the restart on a development install, run `cox chair service
--install` again and the `systemctl` lines it prints. `landing_areas.land_checks` and `land_limit` are opt-in, and
a repository without them lands as before.

Migrations: none
