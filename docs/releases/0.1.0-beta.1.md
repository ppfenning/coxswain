# 0.1.0-beta.1

The first Coxswain release. Every component is tagged `v0.1.0-beta.1`; the manifest table on the
[Releases](index.md) page pins them. Status: **planned**; this page is filled in as the release is
cut. What follows is what landed on 2026-09-05, the day the platform took its name.

## coxswain

- Repository created: `manifest.toml` with lockstep pins, four tests on its shape, CI, the
  `protect-main` ruleset.
- Docs site: MkDocs Material with a beta banner, `mike` versions, GitHub Pages, and the six
  sections written (Start here, Install, Methodology, Customize, Components, Releases).
- PyPI trusted publishers registered for `coxswain` and `coxswain-tools` (workflow
  `publish.yml`, environment `pypi`); `publish.yml` itself is planned.

## cartridges (`coxswain-cartridges`)

- `policy.dispatch.max_in_flight` and the dispatch skill's "fill only the free slots" rule.
- `cartridge.d/*.yaml` fragments fold over each layer in sorted order; tighten-only holds per
  fragment and refusals name the fragment file.
- `layers()` exposes the resolved-so-far cartridge after each layer and fragment; `load` and
  `layers` share one walk.
- `crew` replaces `cast` as the seats key; `cast` accepted as a deprecated alias for one release
  and recorded in `deprecations`. Seat-bound plugin skills are not validated against the harness
  skill index.

## graphs (`coxswain-graphs`)

- The coxswain graph's docket reports in-flight runs and free slots; the driver invokes only that
  many and defers the rest with a reason.
- `validate_chunk` may ask for evidence: a typed `needs_evidence` list of paths the harness reads
  once and attaches before asking again, ending blind "need to verify" quarantines.
- The "chief of staff" graph, docs and prose renamed to coxswain; the registry key stays `cos`
  this release.

## tools (`coxswain-tools`)

- `cox` is the operator command; `agent-tools` stays as an alias for one release.
- `cox route launch cos` starts the coxswain detached and refuses a second live one.
- `cox install --dry-run` and `cox versions`: the pure install planner over the manifest.
- The doctor probe returns the resolved cartridge, the skill index and per-key provenance.
- `runs events`: pure parsers from run records (first of three pieces).

## crew (`coxswain-crew`)

- Renamed from `agent-cast`. No code changes; the cartridge vocabulary it names moved from
  `cast` to `crew`.

## hud (`coxswain-hud`)

- Renamed from `agent-voice-hud`. No code changes this release; spoken run events and the island
  view are planned.

## desktop

- Planned: the Waybar module, the notifier service and the floating `runs top` window, once
  `runs events`, `runs notify`, `runs bar` and `runs top` exist in tools.
