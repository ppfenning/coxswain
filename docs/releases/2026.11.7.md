# 2026.11.7

Cut on 2026-11-13. Status: **beta**. This release changes how work lands and where the board lives. Each initiative now builds on one branch and lands as one pull request, through a landing worker that runs beside the chair. The store is the board and the store is Postgres: the ticket files are a copy written from it, and the workspace no longer has to be a git checkout. The chair's MCP server has a command, and a bare `cox` beside a live chair attaches to it over MCP. **This release needs a Postgres store on every machine; read Upgrading before you install it.**

**Landing.** An initiative has one branch, cut when its first run starts. Phases are cut from it and merge back into it, and the whole initiative goes to its parent as one pull request. `cox lander` does the merging and landing; the chair's tick plans no land for an initiative, and the epic steward is removed. A conflict files a rectify task instead of failing the land, and a rebuild starts from the task's last attempt. Epics can stack their initiatives' pull requests, and initiatives that change no file in common can be checked and merged together.

**The store is the board.** `work_state: files` and the local sqlite store are retired. With `chair.workspace_git: false` the chair pulls and pushes nothing, reads its work from the store, and a decompose on any machine writes its plan there. The courier bus is a table in the store. Commands that read the ticket files refresh them from the store first. A pull from a tracker is also a one-way sync: a queued ticket takes the source's newer text, and an edit after decomposition is recorded on the initiative. Cartridges stay with their owner; a launch publishes the exact files to the store and the lane host writes them itself.

**MCP.** `cox mcp` serves the board, the queue and the cartridge settings to an MCP client. Plain writes run the `cox` command a person would type and return its outcome. With a live chair service, bare `cox` opens a session attached to it over MCP, from any directory, and takes no lease; `cox --workspace` forces the old workspace session.

## Known gaps

None of the landing worker, the store-only board, the cartridge delivery or the MCP server had run against a live workspace when this was cut; they are covered by the test suites only. Nothing acts yet on an upstream edit recorded after decomposition, and only the `github` source re-reads the tickets it already took. A lane host still receives the initiative directory and the intake file by rsync. Some land paths still read the ticket files on purpose, and the chair lock, the notify state, the chat state and the gate policy are still files in the workspace. Files under `intake/held/` are not store rows. Initiatives whose files overlap still land one at a time. An attach beside a chair on another machine reads this machine's cartridge, not the chair's.

## Upgrading

The store schema version is 2026.11.7. This release has no migrations.

Migrations: none

**Every machine needs a Postgres store before it upgrades.** A command that touches the board refuses a profile whose store is not Postgres and says so. On a machine that used the local sqlite store, run `cox setup store --store shared`, then `cox setup store switch shared` to carry its rows over. A profile that says `work_state: files` should drop the key.

After upgrading the chair's machine: run `cox lander adopt` and read its report, then `cox lander adopt --apply`, then `cox lander service --install`. To take the workspace out of git, set `chair.workspace_git: false` in the profile.
