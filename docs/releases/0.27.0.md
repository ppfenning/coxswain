# 0.27.0

Cut on 2026-10-02. `coxswain-tools` is tagged `v0.27.0`. `coxswain-graphs` and `coxswain-dash` stay pinned at
`v0.26.0`, `coxswain-cartridges` at `v0.23.1` and `coxswain-crew` at `v0.12.0`. `coxswain-tools` is published to PyPI
from its tag. Status: **beta**. This release opens intake to work beyond Coxswain itself: any project, with or
without a GitHub remote. It carries three headlines. The coxtop work planned for 0.27 (the chair panel, `cox chair
ask`, the canvas visuals, API runner cost recording) moves to 0.28.

**Intake from a drop folder.** A new built-in source, `folder`. Each Markdown file dropped directly in a configured
folder becomes an intake ticket, titled by its first `# heading` or its file name, and moves into the folder's `done/`
once filed. `repo_map` maps each folder to the repository its tickets target. `cox route pull` with no `--source` now
pulls every source the profile names, in order, so the autonomous chair reads the folder alongside GitHub issues.

```yaml
sources: {"github": {"repos": ["owner/repo"]}, "folder": {"repos": ["~/intake"]}}
repo_map: {"owner/repo": "/path/to/repo", "~/intake": "/path/to/repo"}
```

**Projects with no GitHub remote.** A new built-in forge, `auto`, picks per repository from its `origin`: one on
github.com lands through pull requests and their checks, any other, including one with no remote at all, through plain
git with the land's own checks as the gate. One profile can now hold both kinds of project.

**GitHub intake works with current gh.** gh 2.102 removed the `repository` field from `gh issue list --json`, which
made every GitHub pull fail before it listed anything. The source now reads the repository from each issue's URL.

**Upgrading from 0.26.0.** Nothing migrates. A bare `cox route pull` used to read `github`; it now reads every source
in the profile and says `no sources in the profile` when there are none, so pass `--source github` to keep pulling
one source. Set `forge: auto` to land projects off GitHub. Restart the chair loop after upgrading `cox`.

## coxswain-tools

- A built-in `folder` intake source, and `cox route pull` without `--source` pulls every source the profile names
  (tools #1270).
- The built-in `auto` forge lands a repository through pull requests when its origin is on github.com and through
  plain git otherwise, and the doctor checks gh for it (tools #1272).
- The GitHub intake source lists issues without the `repository` field gh 2.102 removed (tools #1271).
- A doctor test uses a placeholder object-store endpoint (tools #1269).

## coxswain

- The coxswain docs describe the built-in intake sources, `github` and `folder` (coxswain #217).
- The coxswain docs' cargo install line names the crate it installs (coxswain #216).

## Components

`coxswain-tools` carries the intake sources and the auto forge, and the umbrella the docs. `coxswain-graphs`,
`coxswain-dash`, `coxswain-cartridges` and `coxswain-crew` are unchanged.
