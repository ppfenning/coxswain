# 0.12.0

Cut on 2026-09-17. `coxswain-cartridges`, `coxswain-graphs`, `coxswain-tools` and `coxswain-crew` are tagged
`v0.12.0` in lockstep, the crew rejoining the release version with its first change since `v0.7.0`;
`coxswain-tools` is published to PyPI
from its tag. Status: **beta**; nothing here breaks a `0.11.0` install. This release saves a long day's
work before the weekly budget closes: the command table now builds the whole CLI, the release planner
performs its own bumps, the weekly spend ceiling is real, and the operator surfaces that had been waiting
since the sixth land — the in-place drill-down in `cox runs top`, the Waybar line, the home screen's paint
and regatta.

## coxswain-crew

- The crew gains Liam, the courier seat: it reads the courier inbox for the chair's label, resolves each
  reference through the CLI, relays it to its owner in the harness's own words, and acks only what it
  delivered; cheap tier, read-only tools, no write authority beyond the ack (crew #6).

## coxswain-graphs

- The graphs epic writes `initiative` and `phase` into every task record and prints `cox runs land` as the
  remedy for an escalated approval, since `recover` could not resolve a phase without them (graphs #138).
- The graphs fix loop's lint-fix step lands (graphs #139).

## coxswain-tools

- The tools command table now builds every command group — `courier`, `home`, `versions`, `usage`,
  `plan`, `epic`, `stats`, `setup`, `route` and `dev` — from module-level rows in `COMMAND_TABLE`, each
  proven byte-identical by the help snapshot taken before its migration (tools #199, #200, #201, #203,
  #204, #207, #208, #211, #219, #226, #227).
- `cox dev release` in tools lets a planned bump through the gate and executes the bump, push, PR, wait
  and merge steps itself, so a cut needs no hand-made version PRs (tools #217, restored by #222).
- The tools routing profile gains `spend.weekly_ceiling_usd` with a 93 percent hard stop judged by launch,
  context and home alike (tools #210, #211), and the weekly total reads the cost and start time a usage
  file actually carries (tools #221, #222).
- `cox runs top` in tools expands a run in place under its own row on ENTER, collapses on ESC, and keeps
  the expansion while j and k move (tools #214, #215); `cox runs bar` prints one Waybar line with the
  launcher on click (tools #216).
- `cox home` in tools gains its framed layout, the paint pass and the regatta view (tools #212, #218,
  #224); the window pane shows percent of ceiling (tools #220); the stats regime history is backfilled
  (tools #223).
- `cox route file --from-intake` in tools writes word-boundary slugs, surfaces from the body's paths and a
  full ticket frontmatter (tools #205); `cox runs clean` keeps a refused task's draft branch (tools #206);
  the doctor's schema row reads the other two components' versions from their checkouts (tools #202); the notes
  citation check no longer reads a `coxswain://` reference as an umbrella mention (tools #209); launching
  or landing takes the leader lock when nobody holds it (tools #213).

## Known gaps

The render and surface-check steps of the command table are still ahead, as are the home screen's regatta lane and layout, three operator-surface tickets, and the intake sources,
recover record and route sync initiatives; all are filed and fenced. `cox runs clean` keeps the per-task
phase branch of a refused task where it should keep the agents draft. The umbrella's own release check now
runs clean.

## Components

`coxswain-tools` carries nearly all of the changes above; `coxswain-graphs` carries the task-record
fields and the lint-fix step; `coxswain-crew` carries the courier seat and rejoins lockstep at
`v0.12.0`; `coxswain-cartridges` is re-tagged in lockstep with no changes of its own.
