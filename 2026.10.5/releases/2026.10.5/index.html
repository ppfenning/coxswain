    2026.10.5

    Cut on 2026-10-31. Status: beta. A release that places lanes across every host and checks their tools before a launch, adds a live view of what each run is doing, lets a bare cox resume or take over the chair, and narrows the GitHub board to open epics. It also makes landing harder to break, and it adds one store migration.

    Lanes are placed by the hosts table. cox route launch with no --on picks a host from the hosts table, prints the host and its slots in use, and refuses rather than overfill a host. Before any copy it checks that each tool the repo's checks call is on the chosen host's lane PATH, and it refuses with the missing tool's name. Remote lanes build on the chair's current commit, and a launch whose base cannot be resolved on the chair refuses instead of building on a stale one. cox runs wait, runs move and runs stop now see remote lanes and every host in the table.

    A live view of each run. cox runs top shows each run's lease, heartbeat and elapsed time, and a run's nodes expand to show node, turns, last tool and cost. A lane host writes its progress into the store with each heartbeat, so a remote run's progress appears too. A run whose lease another holder took is reported as fenced in runs top, runs detail, status and watch. route launch refuses to relaunch it, and chair clear and cleanup leave live runs alone.

    Bare cox resumes, attaches or takes over the chair. With no label, cox takes a free chair, resumes your own, or offers to take over a live holder's chair, open a session that is not the chair, or cancel. A takeover asks the holder to release and waits a short grace. cox route leader status is new and prints one line saying who holds the chair.

    The GitHub board tracks open epics. Under tracker_scope: epics, only epics get issues, and a settled epic with no issue is skipped unless tracker_backfill: true is set. Each synced epic carries a checklist of its tasks, ticked when a task is done. cox route sync --prune-out-of-scope closes task issues and removes cards outside the narrowed scope; --dry-run lists them first. Sync also refuses a board that lacks a State option, and it sets a Release field and an epic milestone.

    Repos that land on another branch, or by hand. A repo's base: setting, or --base, names the branch it lands on, and runs land, its PRs, runs stranded and the epic harness all use it; phase branches are cut from origin/<base> after a fetch. A repo set to land: manual is skipped by runs land. Once a person merges its PR, the chair marks the task done.

    Landing is harder to break. A land runs the team cartridge's checks and then the repo's own, each line in its own shell in the land worktree. It regenerates a generated file that conflicts instead of aborting, and it keeps its leases renewed while it waits on checks. It takes over a repo lease whose holder process is gone. A task whose land conflicts can be sent back for a rebuild, and the next epic run builds it. A test that fails under parallel workers is rerun once on its own before the task is quarantined. cox stats flaky lists tests that needed that rerun three or more times in a week.

    Fleet state in a herdr pane, and a fix to the five-hour estimate. cox runs herdr reports fleet state to a herdr pane: blocked when work is approved but not landed, or when a lane's host stops renewing its lease. When the usage meter is stale, the five-hour spend estimate now uses the active ccusage block instead of summing from a reset hours or days old. In coxswain-dash, towpath shows spend inside slipstream, gives every pane one status colour map, colours the queue bar by state, and shows in history whether an approved run's tasks landed.

    Known gaps

    The GitHub board changes were tested only against simulated gh output. Rewriting the Release field's options through the GitHub API has not been tried on a real board, and neither has prune's reading of card repositories. cox runs herdr was built against a stand-in for herdr written from its documentation and has not been checked against the real herdr's --help output. cox runs top --once prints the flat table; nodes expand only in the interactive view. A land: manual repo is rechecked every five minutes, so a merged PR can take that long to mark its task done.

    Cut with --allow-doc-drift: release-check reports the same three drifts it reported at 2026.10.4, none introduced here. The dash component page lives at docs/components/dash/, not dash.md. The package description is two sentences. graphs/README.md names the agent-graphs ledger directory, which is still the path the code writes.

    Upgrading

    The store schema moves from version 13 to 14: migration 0014 adds a progress column to the leases table. No manual step is needed. The harness applies the migration the first time it opens the store to write, and it saves a backup copy first; a Postgres store needs pg_dump on the PATH for that backup. cox only reads the store and treats the column as empty until then. An older harness refuses to open a store that is at version 14, so upgrade every lane host that shares a store along with the chair. This release declares no cox migrate migrations.
