    0.6.0

    Cut on 2026-09-15. Every component is tagged v0.6.0 in lockstep; the manifest table on the Releases page pins them. coxswain-tools is published to PyPI from that tag, so uv tool install coxswain-tools gets you the cox command.

    Status: beta, unchanged. Nothing here breaks a 0.5.0 install. Two things change what you see: work items can now read state: approved, and a run's record carries what the harness observed rather than what the seat reported.

    This release closes two of the seven intake groups planned on 2026-09-08 — G1, the observed record, and G2, the landing model — across all three code components, plus the tools half of G3, work shape. The remaining groups follow in 0.7.0.

    The record is observed, not narrated (G1)

    Before this release the platform reconstructed from prose what it already held structurally, and where the prose was absent it held nothing: a budget-stopped run wrote no usage at all, a seat's commands_run was its own account of itself, and one quarantined label covered four different situations. Measured on 2026-09-08, that made 69% of recorded failures spurious and the landed rate an artefact.

    coxswain-graphs now writes facts where they happen. Every call appends to runs/<run>.calls.jsonl as it completes — role, model, cost, turns, result subtype — so a run that dies mid-flight still has a ledger. files_touched and commands_run are derived from the runner's own trace (each Bash tool_use paired with its tool_result), never from the model's summary, and the self-report is kept only when no trace exists, tagged source: self_report. A quarantine has a kind: refused (the reviewers said no), unverified (approved, a check failed after — the patch is kept), infra (a node or provider failed — the patch is kept, the attempt does not count), and dropped. The lifecycle's BUILD_SCHEMA, change_facts and measured_facts read the derived values, and a record without them (older runs, non-build roles) still validates.

    coxswain-tools reads it back. cox stats ingest loads calls.jsonl alongside the trace-recovered figures, anchors events to the run they belong to, and classifies outcomes by kind. cox stats coverage reports known/total provenance rows for runs, calls and tasks, so every headline figure says beside itself how much of the corpus it is computed from. coxswain-cartridges' record_attempt takes kind and patch_kept, so the work item's attempt history carries the same distinction.

    The landing model (G2)

    Ten stale-branch blocks, two hand recoveries after land deleted sibling branches and four lint round-trips in one night made the case: a phase should land as one PR with its tickets stacked inside, and the tooling around it should know what it is looking at.

    • approved and dropped are work-store states (coxswain-cartridges). approved means built, reviewed and approved, merge escalated to a person — not ready, not done. dropped is terminal: done + dropped completes a phase. cox route treats both correctly; a dropped item never reads as ready.
    • cox runs recover <run> <task> --repo PATH exists. Every escalated task's log line named it as the remedy since 0.5.0; now it merges the approved commit into its phase branch.
    • cox runs land plans from the run's own paths, lands a whole phase off its epic branch (--phase), runs the repository's configured checks in a fresh worktree before pushing, and names the failing check and its output tail when one fails.
    • Project checks come from the cartridge — landing_areas.checks is what a build worktree and a land both run, and a project layer may now declare its own list (a bash repository is no longer gated on pytest). An empty list, or an entry whose cmd is blank, is refused.
    • Phase completion is checked before a phase is marked complete (coxswain-graphs): a stale phase branch is recreated from the default branch rather than blocking the run; and one style_pass trim runs per phase, applied only when the set of collected test ids is a superset of what it was and the configured checks still pass — otherwise the phase record says trim: refused (coverage floor) and the branch is untouched.

    Work shape, the tools half (G3)

    cox route launch sweep --idea FILE --initiative-id ID launches the sweep graph for work that is one rule applied in many places. cox route lint <initiative-dir> --repo PATH runs the four static ticket rules — reach, coupling, grant, size — over a filed initiative before anything is dispatched, and cox route groups prints the latest intake grouping. coxswain-graphs carries the pure lint_tickets these rules come from and the worktree library every run exits through; the sweep graph itself and the coxswain's shape decision land in 0.7.0.

    Also in this release

    • The three arms (work item, work state, docs) carry the reviewers' ceiling, so a bookkeeping step can no longer kill an approved task on budget (coxswain-cartridges).
    • ruff is a declared dev dependency in all three code repositories; the cartridge's lint check runs it in every build worktree.
    • Design specs for the remaining groups — validator reach (G4), cost bounds (G5), release discipline (G6), triage and earned autonomy (G7) — are committed under docs/design/ in the repositories they bind; 0.7.0 implements them.

    Known gaps, stated

    • cox dev release-check still reports 48 drifts on a clean tree, all false (44 cli_surface against generated pages, 4 manifest against version-injected pages). This release was cut through them with --allow-doc-drift; G6 fixes the checks.
    • The fix loop can still spend a third build it never reviews; the fix is in flight and lands in 0.7.0.

    Components

    coxswain-graphs carries the observed record, the landing model's harness side and lint_tickets. coxswain-tools carries recover, the land changes, the stats ingest and the three route commands. coxswain-cartridges carries the states, project checks and the arm ceilings. coxswain carries the manifest and these notes. coxswain-crew is unchanged since v0.5.0 and is tagged in lockstep.
